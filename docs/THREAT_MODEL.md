# Threat model

This concise model covers the Tier A trust boundaries: humans and agents submit untrusted inputs; uploaded files and AI output are untrusted; only the server may authorize a payout; external payout results must be authenticated and reconciled. The controls below are defense-in-depth, not a claim that the system is attack-proof.

| Threat | Control | Test evidence |
|---|---|---|
| An agent or user reads another tenant's data | Tenant-scoped repositories, session authorization, and agent ownership checks | [`route-coverage.test.js`](../server/test/security/route-coverage.test.js) checks protected route middleware; [`agents-payees.test.js`](../server/test/integration/agents-payees.test.js) exercises tenant isolation and agent ownership. |
| Forged cross-site mutation using a human session | CSRF token validation on session mutations; agent and webhook authentication use separate mechanisms | [`app-shell-security.test.js`](../server/test/unit/app-shell-security.test.js) checks authenticated feedback and CSRF validation. |
| Malicious or oversized document upload | Stream size cap, magic-byte validation, randomized storage key, and path-safe filename handling; files remain outside static web content | [`documents.test.js`](../server/test/unit/documents.test.js) covers invalid magic bytes, the 10 MB limit, partial-file cleanup, and hostile names. |
| Prompt injection or hidden instructions inside an invoice | Documents are untrusted data; deterministic injection flags remain even if AI analysis fails; AI cannot approve | [`documents.test.js`](../server/test/unit/documents.test.js) tests heuristic detection; [`ai.test.js`](../server/test/unit/ai.test.js) covers classified AI failures and output validation. |
| Forged, duplicated, or premature payout webhook | Provider signature verification, event deduplication, idempotent reconciliation, and retry until execution is durable | [`paypal.test.js`](../server/test/integration/paypal.test.js) covers signatures and deduplication; [`webhook-job.test.js`](../server/test/unit/webhook-job.test.js) covers unknown and premature events. |
| Duplicate payout or provider timeout/crash | Durable execution state and stable provider idempotency ID; uncertain outcomes retain the reservation and require manual review | [`execution.test.js`](../server/test/integration/execution.test.js) exercises concurrent workers, lost responses, retries, and recovery. |
| Credentials or recipient identifiers leak to logs | Structured-log redaction and masked identifiers; provider secrets stay server-side | [`logger.test.js`](../server/test/unit/logger.test.js) checks redaction; [`agents-payees.test.js`](../server/test/integration/agents-payees.test.js) checks response redaction. |
| Ledger payload modification | Hash chaining, signatures, immutable database triggers, and end-of-suite integrity verification | [`final-ledger.test.js`](../server/test/security/final-ledger.test.js) verifies all test tenants and detects six tamper classes. |
| Brute-force requests or key abuse | Per-IP login limit, per-key agent limit, and webhook-token limit | [`auth.test.js`](../server/test/auth.test.js) and [`agent-auth.test.js`](../server/test/unit/agent-auth.test.js) exercise login and agent-key limits; [`paypal.test.js`](../server/test/integration/paypal.test.js) checks webhook rate limiting. |
| Registration abuse and spam flooding | Honeypot field (`website`), 5/hr per-IP, 3/hr per-email rate limits, global 503 daily throttle (`SIGNUP_DAILY_LIMIT`), and 7-day unverified account purge | [`signup.test.js`](../server/test/integration/signup.test.js) verifies honeypot, rate limits, and unverified cleanup. |
| Account enumeration via signup or resend | Constant-time 202 `{ status: "verification_sent" }` response for new, verified, and unverified states; HMAC email in audit logs | [`signup.test.js`](../server/test/integration/signup.test.js) tests identical responses across states and HMAC redaction. |
| Token interception or verification replay | 32-byte CSPRNG token stored as SHA-256 hash, single-use row lock (`SELECT FOR UPDATE`) in atomic transaction, 24h expiry, old token revoked on resend | [`signup.test.js`](../server/test/integration/signup.test.js) tests single use, expiration, old token cancellation, and parallel race. |
| Credential / token exposure in outbox and logs | AES-256-GCM outbox payload encryption with AAD, `SMTP_PASS` and token hash redaction in logger; development mode only prints links to console | [`signup.test.js`](../server/test/unit/signup.test.js) checks logger redaction, outbox encryption, and template disclaimers. |

Coverage is not uniform across every possible production configuration. The route-table test checks middleware declarations; it is not a live cross-tenant request against every route. The ledger establishes internal integrity evidence, not proof that an operator cannot recreate the entire database.
