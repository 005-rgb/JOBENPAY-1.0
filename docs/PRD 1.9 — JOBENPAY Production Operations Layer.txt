# PRD 1.9 — JOBENPAY Production Operations Layer
## Operational Readiness for Real-World Deployment

**Versi:** 1.0 · **Status:** Implementation-ready, Zero-Hallucination  
**Tanggal:** 7 November 2026  
**Basis:** PRD 1.2–1.8 (semua layer fungsional selesai)  
**Prinsip:** Setiap endpoint, konfigurasi, dan test case eksplisit. AI builder tidak perlu menebak. Tidak ada "disiratkan".  
**Tujuan:** Membuat JOBENPAY tidak hanya "secara konsep matang" tetapi juga "siap beroperasi" di lingkungan produksi dengan SLO terukur, observability lengkap, dan prosedur insiden yang teruji.

---

## 0. ATURAN EMAS (NON-NEGOTIABLE)

1. **Setiap SLO memiliki SLI yang terukur.** Tidak ada SLO tanpa metrik.
2. **Setiap alert memiliki runbook.** Tidak ada alert yang tidak dapat ditindaklanjuti.
3. **Setiap kegagalan memiliki circuit breaker.** Tidak ada panggilan eksternal tanpa timeout.
4. **Setiap perubahan memiliki rollback plan yang diuji.** Tidak ada deploy tanpa rollback.
5. **Setiap secret memiliki rotasi.** Tidak ada secret permanen.
6. **Setiap pengecualian memiliki expiry.** Tidak ada "TODO" tanpa tanggal.
7. **Coverage 100%** untuk modul baru (`slo_service.js`, `circuit_breaker.js`, `runbook_service.js`). CI gagal jika < 100%.
8. **Setiap test case memiliki assertion eksplisit** (§9). Tidak ada "test bahwa X berfungsi".

---

## 1. RINGKASAN DAN FILOSOFI

### 1.1 Masalah yang Diselesaikan

PRD 1.2–1.8 membangun sistem yang **secara fungsional lengkap**: mandat, gerbang deterministik, ledger, verifikasi lintas organisasi, DIP, CPL, JPL. Tetapi sistem ini **belum siap produksi** karena:

1. **Tidak ada SLO terukur.** Tim tidak tahu apakah sistem "sehat" atau tidak.
2. **Tidak ada graceful shutdown.** Restart dapat menyebabkan status `EXECUTING` menggantung.
3. **Tidak ada circuit breaker.** Jika PayPal lambat, JOBENPAY ikut menggantung.
4. **Tidak ada per-tenant dashboard.** Support tidak dapat mendiagnosis masalah tenant dalam hitungan detik.
5. **Tidak ada runbook.** On-call engineer tidak tahu apa yang harus dilakukan saat insiden.
6. **Tidak ada rollback teruji.** Rollback plan hanya ada di dokumen, tidak pernah dijalankan.
7. **Tidak ada rotasi secret.** Secret permanen adalah risiko keamanan.
8. **Tidak ada load test realistis.** Kapasitas tidak divalidasi.

### 1.2 Solusi: Production Operations Layer

PRD 1.9 menambahkan **lapisan operasional** yang mencakup:

1. **SLO/SLI Framework** — metrik keandalan yang terukur.
2. **Graceful Shutdown** — menyelesaikan request yang sedang berjalan sebelum keluar.
3. **Circuit Breaker** — mencegah cascade failure.
4. **Observability** — per-tenant dashboard, audit log queryable, distributed tracing.
5. **Runbook** — prosedur eksplisit untuk setiap insiden.
6. **Deployment Readiness** — rollback teruji, canary release, exception tracking.
7. **Secret Management** — rotasi tanpa downtime.
8. **Load Testing** — validasi kapasitas pada 2x peak traffic.

### 1.3 Filosofi

> **"Sistem yang tidak dapat dioperasikan bukanlah sistem. Itu adalah prototipe."**

PRD 1.9 mengubah JOBENPAY dari **prototipe** menjadi **sistem produksi** yang dapat diandalkan, diamati, dan dipulihkan.

## Tujuan
Mendefinisikan apa yang terjadi ketika Error Budget habis.

## Aturan
1. **Jika Error Budget > 50%:** Normal operations.

- Review mingguan: tim engineering + product.
- Keputusan freeze: oleh Engineering Lead.
- Unfreeze: setelah 2 minggu tanpa insiden kritis.

## 4. GRACEFUL SHUTDOWN

### 4.1 Prosedur

**File:** `server/src/shutdown.js`

```javascript
// @ts-check
import { logger } from './lib/logger.js';
import { pool } from './db/pool.js';
import { worker } from './jobs/worker.js';

const SHUTDOWN_TIMEOUT_MS = 30000;

export function setupGracefulShutdown(server) {
  let isShuttingDown = false;

  async function shutdown(signal) {
    if (isShuttingDown) {
      logger.warn({ signal }, 'Shutdown already in progress');
      return;
    }
    isShuttingDown = true;
    logger.info({ signal }, 'Graceful shutdown initiated');

    // 1. Stop accepting new connections
    server.close(() => {
      logger.info('HTTP server closed');
    });

    // 2. Stop worker from claiming new jobs
    worker.pause();

    // 3. Wait for in-flight requests (with timeout)
    const timeout = setTimeout(() => {
      logger.error('Shutdown timeout exceeded, forcing exit');
      process.exit(1);
    }, SHUTDOWN_TIMEOUT_MS);

    try {
      // 4. Wait for worker to finish current jobs
      await worker.drain();
      logger.info('Worker drained');

      // 5. Close database pool
      await pool.end();
      logger.info('Database pool closed');

      clearTimeout(timeout);
      logger.info('Graceful shutdown complete');
      process.exit(0);
    } catch (err) {
      logger.error({ err }, 'Error during shutdown');
      clearTimeout(timeout);
      process.exit(1);
    }
  }

  process.on('SIGTERM', () => shutdown('SIGTERM'));
  process.on('SIGINT', () => shutdown('SIGINT'));
}
```

### 4.2 Worker Pause/Drain

**File:** `server/src/jobs/worker.js` (modifikasi)

```javascript
// Tambahkan method pause() dan drain()
class Worker {
  constructor() {
    this.paused = false;
    this.activeJobs = new Set();
  }

  pause() {
    this.paused = true;
  }

  async drain() {
    while (this.activeJobs.size > 0) {
      await new Promise(resolve => setTimeout(resolve, 100));
    }
  }

  async processJob(job) {
    if (this.paused) return;
    this.activeJobs.add(job.id);
    try {
      await this.executeJob(job);
    } finally {
      this.activeJobs.delete(job.id);
    }
  }
}
```

// @ts-check
import { Router } from 'express';
import { pool } from '../db/pool.js';
import { worker } from '../jobs/worker.js';
import { migrationStatus } from '../db/migrations.js';

const router = Router();

// Liveness: hanya cek process alive
router.get('/healthz', (req, res) => {
  res.status(200).json({ status: 'ok', timestamp: new Date().toISOString() });
});

// Readiness: cek DB, migrasi, worker heartbeat
router.get('/readyz', async (req, res) => {
  const checks = {
    database: false,
    migrations: false,
    worker_heartbeat: false
  };

  try {
    const dbResult = await pool.query('SELECT 1');
    checks.database = dbResult.rowCount === 1;
  } catch (err) {
    // database false
  }

  try {
    checks.migrations = await migrationStatus();
  } catch (err) {
    // migrations false
  }

  try {
    checks.worker_heartbeat = worker.isAlive();
  } catch (err) {
    // worker false
  }

  const allReady = Object.values(checks).every(v => v === true);
  res.status(allReady ? 200 : 503).json({
    status: allReady ? 'ready' : 'not_ready',
    checks,
    timestamp: new Date().toISOString()
  });
});

// Startup: cek migrasi selesai
router.get('/startupz', async (req, res) => {
  try {
    const ready = await migrationStatus();
    res.status(ready ? 200 : 503).json({ status: ready ? 'started' : 'starting' });
  } catch (err) {
    res.status(503).json({ status: 'error' });
  }
});

export default router;
```

## 5. CIRCUIT BREAKER

### 5.1 Implementasi

**File:** `server/src/lib/circuit-breaker.js`

```javascript
// @ts-check
import { logger } from './logger.js';

export class CircuitBreaker {
  constructor(name, options = {}) {
    this.name = name;
    this.failureThreshold = options.failureThreshold || 5;
    this.successThreshold = options.successThreshold || 2;
    this.timeout = options.timeout || 30000;  // 30s
    this.resetTimeout = options.resetTimeout || 60000;  // 60s

    this.state = 'CLOSED';  // CLOSED, OPEN, HALF_OPEN
    this.failures = 0;
    this.successes = 0;
    this.nextAttempt = Date.now();
  }

  async execute(fn) {
    if (this.state === 'OPEN') {
      if (Date.now() < this.nextAttempt) {
        throw new Error(`Circuit ${this.name} is OPEN`);
      }
      this.state = 'HALF_OPEN';
    }

    try {
      const result = await Promise.race([
        fn(),
        new Promise((_, reject) =>
          setTimeout(() => reject(new Error('Timeout')), this.timeout)
        )
      ]);
      this.onSuccess();
      return result;
    } catch (err) {
      this.onFailure();
      throw err;
    }
  }

  onSuccess() {
    this.failures = 0;
    if (this.state === 'HALF_OPEN') {
      this.successes++;
      if (this.successes >= this.successThreshold) {
        this.state = 'CLOSED';
        this.successes = 0;
        logger.info({ name: this.name }, 'Circuit CLOSED');
      }
    }
  }

  onFailure() {
    this.failures++;
    if (this.failures >= this.failureThreshold) {
      this.state = 'OPEN';
      this.nextAttempt = Date.now() + this.resetTimeout;
      logger.warn({ name: this.name, failures: this.failures }, 'Circuit OPEN');
    }
  }

  getState() {
    return {
      name: this.name,
      state: this.state,
      failures: this.failures,
      next_attempt: new Date(this.nextAttempt).toISOString()
    };
  }
}

// Circuit breaker registry
const breakers = new Map();

export function getCircuitBreaker(name, options) {
  if (!breakers.has(name)) {
    breakers.set(name, new CircuitBreaker(name, options));
  }
  return breakers.get(name);
}

export function getAllCircuitBreakers() {
  return Array.from(breakers.values()).map(b => b.getState());
}
```

# Runbook: Database Down

## Symptom
- `/readyz` returns 503 with `database: false`.
- Logs show `ECONNREFUSED` or `ETIMEDOUT`.
- All requests return 503.

## Impact
- All transactions halted.
- No new decisions possible.

## Diagnosis
1. Check database connectivity:
   ```bash
   psql $DATABASE_URL -c "SELECT 1"
   ```
2. Check connection pool:
   ```bash
   curl -s localhost:3000/api/v1/ops/db-pool | jq
   ```
3. Check PostgreSQL logs:
   ```bash
   tail -f /var/log/postgresql/postgresql.log
   ```

## Resolution
1. **If database is down:**
   - Restart PostgreSQL: `sudo systemctl restart postgresql`
   - If restart fails, check disk space: `df -h`
   - If disk full, clean up old logs: `find /var/log/postgresql -name "*.log" -mtime +7 -delete`

2. **If connection pool exhausted:**
   - Check active connections: `SELECT count(*) FROM pg_stat_activity;`
   - Kill idle connections: `SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE state = 'idle' AND state_change < now() - interval '10 minutes';`
   - Increase pool size if needed.

3. **If network issue:**
   - Check firewall rules.
   - Check VPC peering (if cloud).
   - Check DNS resolution: `nslookup db.jobenpay.io`

## Escalation
- If not resolved in 15 minutes, escalate to Database Administrator.
- If data loss suspected, escalate to CTO immediately.

## Post-Incident
- Write post-mortem within 48 hours.
- Update runbook if new scenario discovered.
- Update SLO if necessary.
```

## 9. SECRET ROTATION

### 9.1 Prosedur

**File:** `server/src/services/secret_rotation.js`

```javascript
// @ts-check
import { pool } from '../db/pool.js';
import { logger } from '../lib/logger.js';
import { encrypt, decrypt } from '../lib/crypto.js';

const ROTATION_GRACE_PERIOD_MS = 3600000;  // 1 hour

/**
 * Rotasi API key untuk agen.
 * Key lama tetap valid selama grace period.
 */
export async function rotateAgentApiKey(agentId, orgId, userId) {
  const client = await pool.connect();
  try {
    await client.query('BEGIN');

    // 1. Ambil key lama
    const oldKey = await client.query(
      `SELECT key_id, key_hash FROM agent_api_keys 
       WHERE agent_id = $1 AND org_id = $2 AND revoked_at IS NULL`,
      [agentId, orgId]
    );

    // 2. Generate key baru
    const newKey = generateApiKey();
    const newKeyHash = hashApiKey(newKey);

    // 3. Insert key baru
    await client.query(
      `INSERT INTO agent_api_keys (agent_id, org_id, key_hash, prefix, created_by, grace_until)
       VALUES ($1, $2, $3, $4, $5, $6)`,
      [agentId, orgId, newKeyHash, newKey.prefix, userId, new Date(Date.now() + ROTATION_GRACE_PERIOD_MS)]
    );

    // 4. Set grace period untuk key lama
    await client.query(
      `UPDATE agent_api_keys SET grace_until = $1 
       WHERE agent_id = $2 AND org_id = $3 AND revoked_at IS NULL AND key_id != $4`,
      [new Date(Date.now() + ROTATION_GRACE_PERIOD_MS), agentId, orgId, newKey.key_id]
    );

    await client.query('COMMIT');

    logger.info({ agentId, orgId }, 'API key rotated');
    return { new_key: newKey.raw, expires_at: new Date(Date.now() + ROTATION_GRACE_PERIOD_MS).toISOString() };
  } catch (err) {
    await client.query('ROLLBACK');
    throw err;
  } finally {
    client.release();
  }
}

/**
 * Rotasi signing key untuk ledger.
 * Entri lama tetap valid dengan key lama.
 */
export async function rotateLedgerSigningKey(orgId) {
  const client = await pool.connect();
  try {
    await client.query('BEGIN');

    // 1. Ambil key lama
    const oldKey = await client.query(
      `SELECT kid, private_key_enc, public_key_jwk FROM ledger_signing_keys 
       WHERE org_id = $1 AND status = 'ACTIVE'`,
      [orgId]
    );

    // 2. Generate key baru
    const newKey = generateEd25519Key();
    const newKid = generateKid();

    // 3. Insert key baru (status ACTIVE)
    await client.query(
      `INSERT INTO ledger_signing_keys (org_id, kid, private_key_enc, public_key_jwk, status)
       VALUES ($1, $2, $3, $4, 'ACTIVE')`,
      [orgId, newKid, encrypt(newKey.privateKey), newKey.publicKey]
    );

    // 4. Set key lama ke status ROTATED (tetap valid untuk verifikasi)
    await client.query(
      `UPDATE ledger_signing_keys SET status = 'ROTATED', rotated_at = now()
       WHERE org_id = $1 AND kid = $2`,
      [orgId, oldKey.rows[0].kid]
    );

    await client.query('COMMIT');

    logger.info({ orgId, newKid }, 'Ledger signing key rotated');
    return { new_kid: newKid };
  } catch (err) {
    await client.query('ROLLBACK');
    throw err;
  } finally {
    client.release();
  }
}
```

# Capacity Model

## Assumptions
- 10.000 tenants
- 1000 active agents per tenant

- Total: 1 billion transactions/day (peak: 50.000 TPS)

## Per-Instance Capacity
- Node.js 22 instance (4 vCPU, 8GB RAM)

- Database: PostgreSQL with 50 connections per instance × 100 = 5000 connections
- PgBouncer: `default_pool_size = 5000`, `max_client_conn = 10000`

## Cost Estimate
- 100 Node.js instances: ~$5000/month
- PostgreSQL (managed): ~$3000/month
- PgBouncer: ~$500/month
