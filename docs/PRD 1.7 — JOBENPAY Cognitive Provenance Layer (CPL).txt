# PRD 1.7 — JOBENPAY Cognitive Provenance Layer (CPL)
## Membuktikan Bahwa Keputusan AI Dapat Direproduksi, Bukan Hanya Konsisten

**Versi:** 1.0 · **Status:** Implementation-ready, zero-hallucination, dewa-level  
**Tanggal:** 7 November 2026  
**Basis:** PRD 1.2–1.6 (terutama DIP 1.6)  
**Prinsip:** Setiap field, algoritma, state, dan test eksplisit. AI builder tidak perlu menebak. Tidak ada "disiratkan".

---

## 0. ATURAN EMAS (NON-NEGOTIABLE)

1. **Reproducibility, bukan hanya consistency.** DIP 1.6 memverifikasi bahwa alasan agen konsisten dengan niat. CPL 1.7 memverifikasi bahwa **keputusan yang sama dapat direproduksi dari data yang sama**, dengan model yang sama, dalam kondisi yang sama.
2. **Deterministic replay wajib.** Setiap keputusan yang melewati DIP harus dapat **diputar ulang** (replay) dari `Cognitive Snapshot` yang disimpan.
3. **Cognitive Snapshot adalah artefak kriptografis.** Hash-nya ditandatangani dan dimasukkan ke SAR.
4. **Model-agnostic.** CPL tidak bergantung pada model AI tertentu. Snapshot menyimpan **model ID, versi, dan parameter** yang digunakan.
5. **Fail-closed.** Jika replay tidak dapat dilakukan (snapshot hilang, model tidak tersedia), keputusan → `REQUIRE_APPROVAL` dengan kode `CPL_REPLAY_UNAVAILABLE`.
6. **Coverage 100%** untuk `cpl_service.js`, `snapshot_service.js`, dan `replay_engine.js`.
7. **Adversarial corpus 50+ skenario** untuk test.
8. **Tidak ada PII di Cognitive Snapshot.** Hanya hash, ID, enum, angka, timestamp, dan **pointer ke data** (bukan data itu sendiri).

## 1. RINGKASAN DAN FILOSOFI

### 1.1 Masalah yang Diselesaikan

PRD 1.6 (DIP) menjawab: **"Apakah keputusan agen konsisten dengan niat manusia?"**

Tetapi ada pertanyaan yang **lebih dalam** dan **belum dijawab oleh siapa pun di industri**:

**"Jika kita memutar ulang proses pengambilan keputusan dengan data yang sama, model yang sama, dan kondisi yang sama — apakah kita akan mendapatkan keputusan yang sama?"**

Jika jawabannya **tidak**, maka keputusan itu **tidak dapat dipercaya** — bahkan jika DIP = 100. Karena itu berarti keputusan itu **tidak deterministik**, dan bisa berubah karena fluktuasi kecil (suhu model, urutan token, dll.).

Jika jawabannya **ya**, maka kita memiliki **bukti kriptografis** bahwa keputusan itu **dapat direproduksi**, dan oleh karena itu **dapat dipertanggungjawabkan**.

### 1.2 Solusi: Cognitive Provenance Layer (CPL)

CPL menambahkan **lapisan keempat** di atas kontrol eksekusi (1.2), kontrol transaksi (1.3), verifikasi lintas organisasi (1.4–1.5), dan decision integrity (1.6):

1. **Cognitive Snapshot** — rekaman lengkap dari semua input yang mempengaruhi keputusan: prompt, data dokumen (hash), model ID, parameter, seed, konteks retrieval, dll.
2. **Deterministic Replay** — menjalankan ulang model dengan snapshot yang sama, dan membandingkan output.
3. **Reproducibility Score (RS)** — skor 0–100 yang menunjukkan seberapa konsisten replay dengan keputusan asli.
4. **Provenance Chain** — rantai hash yang menghubungkan snapshot, replay, dan keputusan asli.
5. **Human Review Trigger** — jika RS < ambang, transaksi → `REQUIRE_APPROVAL`.

### 1.3 Filosofi

> **"Kepercayaan bukan tentang 'apakah keputusan ini benar'. Kepercayaan adalah tentang 'apakah keputusan ini dapat direproduksi'. Jika tidak dapat direproduksi, itu bukan keputusan — itu kebetulan."**

Ini adalah pergeseran dari **"decision integrity"** (1.6) menjadi **"decision reproducibility"** (1.7). Dan ini adalah **lapisan terakhir** yang diperlukan sebelum agen AI dapat dipercaya untuk mengeluarkan uang besar.

### 3.3 Aturan Snapshot

1. **Snapshot wajib dibuat** untuk setiap transaksi yang melewati DIP (1.6).
2. **Hash dihitung** atas canonical JSON dari snapshot (tanpa field `snapshot_hash` dan `signature`).
3. **Signature** menggunakan Ed25519 (kunci server JOBENPAY).
4. **Tidak ada PII** — hanya hash, ID, enum, angka, timestamp.
5. **Pointer ke data, bukan data itu sendiri** — `document_hashes` menunjuk ke `documents.sha256`, bukan isi dokumen.
6. **Tool calls** direkam sebagai `(tool_name, input_hash, output_hash)` — bukan input/output lengkap.

## 4. ALGORITMA DETERMINISTIC REPLAY

### 4.1 Prosedur Replay

```
1. Ambil snapshot dari database.
2. Verifikasi snapshot_hash dan signature.
3. Ambil data asli berdasarkan hash:
   - document_hashes → dokumen asli dari `documents` table
   - user_prompt_hash → prompt asli dari `request_evaluations` (raw)
   - retrieval_context_hash → konteks retrieval asli
4. Jalankan model dengan parameter dari snapshot:
   - provider, model_id, model_version
   - temperature, top_p, seed, max_tokens
   - system_prompt (dari hash)
   - user_prompt (dari hash)
   - context (dari hash)
5. Bandingkan output baru dengan output asli:
   - decision
   - reasoning_trace_hash
   - raw_output_hash
6. Hitung Reproducibility Score (RS).
```

### 4.2 Formula Reproducibility Score (RS)

```
RS = 100 × (w_decision × R_decision + w_reasoning × R_reasoning + w_raw × R_raw)
```

**Bobot (eksplisit):**

| Komponen | Bobot | Deskripsi |
|---|---|---|
| `w_decision` | 0.50 | Kesesuaian decision |
| `w_reasoning` | 0.30 | Kesesuaian reasoning trace hash |
| `w_raw` | 0.20 | Kesesuaian raw output hash |

**Total bobot = 1.00.**

### 4.3 Komponen R_decision (0 atau 1)

```
R_decision = 1 if replay.decision == original.decision
              else 0
```

### 4.4 Komponen R_reasoning (0, 0.5, atau 1)

```
R_reasoning = 1 if replay.reasoning_trace_hash == original.reasoning_trace_hash
               else 0.5 if semantic_similarity(replay.reasoning_trace, original.reasoning_trace) >= 0.9
               else 0
```

**Semantic similarity:** dihitung dengan **deterministic** algoritma (bukan ML):
- Bandingkan setiap reason (claim, evidence_ref, data_source).
- Jika ≥ 90% reason cocok (exact match pada evidence_ref, fuzzy match pada claim dengan Levenshtein ≤ 10%), maka similarity = 1.
- Jika ≥ 70% cocok, similarity = 0.5.
- Jika < 70%, similarity = 0.

### 4.5 Komponen R_raw (0 atau 1)

```
R_raw = 1 if replay.raw_output_hash == original.raw_output_hash
         else 0
```

### 4.6 Ambang (Eksplisit)

| RS | Keputusan |
|---|---|
| ≥ 90 | `AUTO_APPROVE` (jika semua Tahap A lain lulus) |
| 70–89 | `REQUIRE_APPROVAL` (kode `CPL_LOW_REPRODUCIBILITY`) |
| < 70 | `REJECTED` (kode `CPL_CRITICAL`) |

### 4.7 Contoh Perhitungan

**Original:** decision = APPROVED, reasoning_trace_hash = X, raw_output_hash = Y.
**Replay:** decision = APPROVED, reasoning_trace_hash = X, raw_output_hash = Y.

- `R_decision = 1`
- `R_reasoning = 1`
- `R_raw = 1`

```
RS = 100 × (0.50×1 + 0.30×1 + 0.20×1) = 100
```

**Replay dengan decision berbeda:**

- `R_decision = 0`
- `R_reasoning = 0`
- `R_raw = 0`

```
RS = 0 → REJECTED (CPL_CRITICAL)
```

## 5. SKEMA DATA

### 5.1 Tabel Baru

```sql
-- 5.1.1 Cognitive Snapshots
CREATE TABLE cognitive_snapshots (
  snapshot_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  request_id UUID NOT NULL REFERENCES transaction_intents(intent_id),
  org_id UUID NOT NULL REFERENCES organizations(org_id),
  model JSONB NOT NULL,
  inputs JSONB NOT NULL,
  outputs JSONB NOT NULL,
  environment JSONB,
  snapshot_hash TEXT NOT NULL,
  signature TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE(request_id)
);

CREATE INDEX idx_cognitive_snapshots_request ON cognitive_snapshots(request_id);
CREATE INDEX idx_cognitive_snapshots_org ON cognitive_snapshots(org_id);
CREATE INDEX idx_cognitive_snapshots_hash ON cognitive_snapshots(snapshot_hash);

-- 5.1.2 Replay Results
CREATE TABLE replay_results (
  replay_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  snapshot_id UUID NOT NULL REFERENCES cognitive_snapshots(snapshot_id),
  org_id UUID NOT NULL REFERENCES organizations(org_id),
  replay_model JSONB NOT NULL,
  replay_outputs JSONB NOT NULL,
  reproducibility_score INT NOT NULL CHECK (reproducibility_score BETWEEN 0 AND 100),
  components JSONB NOT NULL,
  decision TEXT NOT NULL CHECK (decision IN ('AUTO_APPROVE','REQUIRE_APPROVAL','REJECTED')),
  replay_hash TEXT NOT NULL,
  replayed_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_replay_results_snapshot ON replay_results(snapshot_id);
CREATE INDEX idx_replay_results_org_score ON replay_results(org_id, reproducibility_score);
```

## 6. INTEGRASI DENGAN DECISION ENGINE

### 6.1 Tahap A Baru (setelah DIP 1.6)

```javascript
// Di decision_engine.js, setelah DIP:
if (mandate.ai.intentCheck === true) {
  const snapshot = await getCognitiveSnapshot(transaction.intent_id);
  if (!snapshot) {
    return { decision: 'REQUIRE_APPROVAL', reason_codes: ['CPL_SNAPSHOT_MISSING'] };
  }

  const replay = await replaySnapshot(snapshot);
  if (!replay.available) {
    return { decision: 'REQUIRE_APPROVAL', reason_codes: ['CPL_REPLAY_UNAVAILABLE'] };
  }

  const rs = computeReproducibilityScore(replay, snapshot);

  if (rs < 70) {
    return { decision: 'REJECT', reason_codes: ['CPL_CRITICAL'], rs_score: rs };
  }

  if (rs < 90) {
    return { decision: 'REQUIRE_APPROVAL', reason_codes: ['CPL_LOW_REPRODUCIBILITY'], rs_score: rs };
  }

  // Lanjut ke Tahap B
}
```

## 13. PRINSIP NON-NEGOTIABLE

1. **Reproducibility, bukan hanya consistency.** CPL memverifikasi bahwa keputusan dapat direproduksi, bukan hanya konsisten.
2. **Snapshot adalah artefak kriptografis.** Hash ditandatangani dan dimasukkan ke SAR.
3. **Model-agnostic.** CPL tidak bergantung pada model AI tertentu.
4. **Fail-closed.** Replay tidak tersedia → REQUIRE_APPROVAL.
5. **Tidak ada PII.** Hanya hash, ID, enum, angka, timestamp.
6. **Coverage 100%.** CI gagal jika < 100%.
7. **Zero ambiguity.** Setiap field, bobot, test eksplisit.
8. **Deterministic replay.** Menggunakan snapshot, bukan memanggil model lagi secara acak.

```
1. Agen mengusulkan SALE: Apple MacBook Pro, $1900, RAM 32GB.

5. RS = 100.
6. Decision: AUTO_APPROVE.
7. SAR memuat cognitive_provenance.reproducibility_score = 100.
```

### A.2 Alur Reproducibility Rendah (RS < 70)

```
1. Agen mengusulkan SALE: Lenovo ThinkPad, $1800, RAM 32GB.
2. DIP: 90 (brand mismatch → hard rule → REQUIRE_APPROVAL).
3. Cognitive Snapshot: model=gpt-4o, temp=0.7, seed=42.
4. Replay: model=gpt-4o, temp=0.7, seed=42 → decision BERBEDA (APPROVED vs REQUIRE_APPROVAL).
5. R_decision = 0, R_reasoning = 0, R_raw = 0 → RS = 0.
6. Decision: REJECTED (CPL_CRITICAL).
7. SAR memuat cognitive_provenance.reproducibility_score = 0.
```

### A.3 Alur Reproducibility Sedang (70 ≤ RS < 90)

```
1. Agen mengusulkan SALE: Apple MacBook Pro, $1900, RAM 32GB.

3. Cognitive Snapshot: model=gpt-4o, temp=0, seed=42.

6. Decision: REQUIRE_APPROVAL (CPL_LOW_REPRODUCIBILITY).
```
